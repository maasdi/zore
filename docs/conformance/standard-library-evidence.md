# Standard-library executable evidence

Source-evidence catalog for issue #211, originally audited against baseline `edcf584` and refreshed against current upstream baseline `4210225`. It maps the locked contracts in specification §37.1–§37.14 to named executable assertions. The evidence is deliberately bounded: bundled source declarations and implementation bodies establish the supplied API, while the listed tests establish only the observations they assert. This catalog does not claim exhaustive coverage of every function, input, host, or combination, and it reports no new test run.

The §37.3 follow-up for issue #220 adds
[subprocess conformance](../../tests/conformance/exec.md).
[tests/codegen/subprocess.rs](../../tests/codegen/subprocess.rs) names direct
assertions for environment presence and child overrides, binary streaming and
cached status, gated cancellation/cleanup, bounded capture, streams shared with
the parent, and the `RunWith`/`OutputWith`/`CombinedOutputWith` options,
deadlines and `Pipe` rejections.
[tests/packages/exec.rs](../../tests/packages/exec.rs) checks private Move
resources, `std/io` composition and helper suspension; runtime `exec` tests
inspect handle removal, untaken pipe closure and reaped child state. These cases
use a Rust child fixture on each host rather than a Unix shell. They establish
direct-child behavior, with no descendant process-tree guarantee.

[compiler/src/driver/stdlib.rs](../../compiler/src/driver/stdlib.rs) registers exactly 47 bundled package paths: `std/archive`, `std/bufio`, `std/bytes`, `std/compress/flate`, `std/compress/gzip`, `std/context`, `std/crypto/hmac`, `std/crypto/rand`, `std/crypto/sha1`, `std/crypto/sha256`, `std/crypto/sha512`, `std/crypto/subtle`, `std/encoding/base64`, `std/encoding/binary`, `std/encoding/csv`, `std/encoding/hex`, `std/encoding/html`, `std/encoding/json`, `std/errors`, `std/flag`, `std/fmt`, `std/hash/crc32`, `std/io`, `std/log`, `std/log/rolling`, `std/maps`, `std/math`, `std/math/rand`, `std/mime`, `std/net`, `std/net/http`, `std/net/url`, `std/os`, `std/os/exec`, `std/os/signal`, `std/path`, `std/path/filepath`, `std/regexp`, `std/slices`, `std/sort`, `std/strconv`, `std/strings`, `std/sync`, `std/testing`, `std/time`, `std/unicode`, and `std/unicode/utf8`. These paths bundle `.ore` sources, with selected runtime declarations. `path/filepath` substitutes a Windows source file on Windows. Cargo sets `autotests = false`; target registrations are explicit in [compiler/Cargo.toml](../../compiler/Cargo.toml). Native tests named below are compiled under its `native` target through modules declared in `tests/codegen/native.rs`; HTTP, JSON, signal, URL/client, log/rolling and other nested suites are not standalone Cargo targets. The external crypto, TLS and SQLite packages are maintained native-adapter examples, not part of the 47 bundled packages.

## External native package status outside §37

SQLite is a maintained external `sqlite` package with a curated native adapter; it is neither one of the bundled standard paths nor a §37 contract. The registered [`tests/driver/sqlite.rs`](../../tests/driver/sqlite.rs)::`sqlite_resource_contract_and_tagged_offline_application` invokes `zore test sqlite` and asserts “23 passed,” an offline tagged dependency, app output and adapter integrity. In [`packages/sqlite/sqlite_test.ore`](../../packages/sqlite/sqlite_test.ore), `TestParametersAndOwnedRows` checks null/numeric/text/binary bindings and owned result survival; `TestTransactions` checks commit, rollback and completed-handle rejection; `TestAsyncResourceAcrossWaits` checks a live statement after suspension; `TestTransactionCallbackErrorRollsBack` and `TestTransactionBusyCommitRollsBackAfterTimeout` check rollback; `TestTransactionCommitWaitsForReaderWithinBusyTimeout` checks retry after a reader releases. The `.ore` cases execute because the Rust driver explicitly invokes the app test runner; Cargo does not discover them directly.

The `.ore` crypto/TLS/SQLite-style application tests are not Cargo-discovered Rust tests. Only the driver functions above make them executed evidence by calling `zore test`; package source presence alone does not. The test registrations and exact test names here identify executable assertions, not results for this audit or proof of the entire §37 API.
