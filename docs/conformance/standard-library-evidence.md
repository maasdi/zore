# Standard-library executable evidence

Source-evidence catalog for issue #211, originally audited against baseline `edcf584` and refreshed against current upstream baseline `4210225`. It maps the locked contracts in specification §37.1–§37.13 to named executable assertions. The evidence is deliberately bounded: bundled source declarations and implementation bodies establish the supplied API, while the listed tests establish only the observations they assert. This catalog does not claim exhaustive coverage of every function, input, host, or combination, and it reports no new test run.

[compiler/src/driver/stdlib.rs](../../compiler/src/driver/stdlib.rs) registers exactly 30 bundled package paths: `std/bufio`, `std/bytes`, `std/context`, `std/errors`, `std/encoding/base64`, `std/encoding/binary`, `std/encoding/hex`, `std/encoding/json`, `std/fmt`, `std/io`, `std/log`, `std/log/rolling`, `std/maps`, `std/math`, `std/net`, `std/net/url`, `std/net/http`, `std/os`, `std/os/exec`, `std/os/signal`, `std/path`, `std/path/filepath`, `std/slices`, `std/sort`, `std/strconv`, `std/strings`, `std/sync`, `std/time`, `std/unicode`, and `std/unicode/utf8`. These paths bundle `.ore` sources, with selected runtime declarations. `path/filepath` substitutes a Windows source file on Windows. Cargo sets `autotests = false`; target registrations are explicit in [compiler/Cargo.toml](../../compiler/Cargo.toml). Native tests named below are compiled under its `native` target through modules declared in `tests/codegen/native.rs`; HTTP, JSON, signal, URL/client, log/rolling and other nested suites are not standalone Cargo targets. The external crypto, TLS and SQLite packages are maintained native-adapter examples, not part of the 30 bundled packages.

## External native package status outside §37

SQLite is a maintained external `sqlite` example package with a curated native adapter; it is neither one of the bundled standard paths nor a §37 contract. The registered [`tests/driver/sqlite.rs`](../../tests/driver/sqlite.rs)::`sqlite_resource_contract_and_tagged_offline_application` invokes `zore test sqlite` and asserts “23 passed,” an offline tagged dependency, app output and adapter integrity. In [`examples/sqlite-library/sqlite/sqlite_test.ore`](../../examples/sqlite-library/sqlite/sqlite_test.ore), `TestParametersAndOwnedRows` checks null/numeric/text/binary bindings and owned result survival; `TestTransactions` checks commit, rollback and completed-handle rejection; `TestAsyncResourceAcrossWaits` checks a live statement after suspension; `TestTransactionCallbackErrorRollsBack` and `TestTransactionBusyCommitRollsBackAfterTimeout` check rollback; `TestTransactionCommitWaitsForReaderWithinBusyTimeout` checks retry after a reader releases. The driver’s [`tests/driver/sqlite.rs`](../../tests/driver/sqlite.rs)::`cleanup_modes` helper, called by that test, asserts normal/error/panic cleanup and contention. The `.ore` cases execute because the Rust driver explicitly invokes the app test runner; Cargo does not discover them directly.

The `.ore` crypto/TLS/SQLite-style application tests are not Cargo-discovered Rust tests. Only the driver functions above make them executed evidence by calling `zore test`; package source presence alone does not. The test registrations and exact test names here identify executable assertions, not results for this audit or proof of the entire §37 API.
