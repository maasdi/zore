# Code style

- Do not comment code by default. Let clear variable, function, method, and type names describe what the code does.
- Add a comment only when it is truly necessary, such as a non-obvious reason, a safety constraint, or a workaround. Keep it to one short line.
- Do not reference other documents or Markdown files in code or comments. That means no spec section numbers, no file paths to docs, and no "see X.md".
