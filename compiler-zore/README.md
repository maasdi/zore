# Zore compiler written in Zore

This folder holds the first stage of the staged self-hosting plan in
`docs/proposals/self-hosting-plan.md`: a lexer written in Zore, checked against
the Rust lexer in `compiler/src/lexer/`. The Rust compiler remains the
reference and bootstrap compiler. Nothing here parses, type-checks, or compiles
programs, and this is not a self-compilation claim.

## Contents

- `lexer/` is the `lexer` package. `lexer.Lex(text)` takes source text that has
  already passed UTF-8 validation. It returns every token with its kind, byte
  span, and decoded literal, plus the lexical errors with their byte spans.
- `lexer/unicode.ore` is a generated table of non-ASCII letters and digits, as
  Rust's `char::is_alphanumeric` defines them for the pinned toolchain.
- `oracle/` is a small program for the comparison test. It reads `cases.bin`
  from the current folder and prints one record per line for each case. It is
  not a compiler driver.

## Commands

Build the Rust compiler first, then run from the repository root:

```sh
cargo test --locked --test selfhost_lexer
ZORE_LEXER_SEED=12345 cargo test --locked --test selfhost_lexer seeded
ZORE_WRITE_UNICODE_TABLE=1 cargo test --locked --test selfhost_lexer unicode_table
```

The first command builds `oracle/main.ore` with the Rust compiler. It feeds the
same bytes to both lexers and compares their records. The second command
explores another seed for the generated inputs; the default seed is fixed, so
ordinary runs are reproducible. The third command regenerates the Unicode table
after a toolchain upgrade. Without the variable, that test fails if the
committed table is out of date.

A mismatch report names the case and its input, then shows the first record
that differs and both full record lists. Generated cases are named by seed and
index, so any reported case can be reproduced.

## Comparison records

Each token is a line of the form `<kind> <start> <end>`. The kind is one of the
following:

- `ident` or `underscore`
- `keyword:<spelling>` or `reserved:<spelling>`
- `int:<base>` or `float`
- `string:<code points joined by .>` or `rune:<code point>`
- `malformed` or `unknown`
- `punct:<spelling>`
- `semi:explicit`, `semi:newline`, or `semi:eof`
- `eof`

Each error is a line `error:<code> <start> <end>`. The codes are fixed names
such as `unterminated-string` or `invalid-digit`. The test maps each Rust lexer
message to one of them, and an unmapped message fails the test. Offsets are
byte offsets. A case whose bytes are not UTF-8 gives the single record
`invalid-utf8`. That check happens before lexing: in Rust it is done by
`SourceMap::load`, and in Zore by `strings.FromBytes`.

## Coverage

Every token form of the Rust lexer is implemented and compared:

- identifiers, `_`, keywords, and reserved words, including the diagnostic for
  a non-ASCII letter in a name
- line and block comments, including unterminated ones
- semicolon insertion at newlines, at multiline block comments, at CRLF line
  ends, and at the end of the file
- double-quoted strings and their escapes, raw strings, and runes
- integers in every base, floats, digit separators, and malformed numbers
- every operator, `++` and `--` rejection, and unexpected characters

The inputs come from five places:

- targeted cases: empty input, whitespace, Unicode, CRLF, and malformed forms
- each line of `tests/lexer/lexer.rs`, and the whole file
- the lexical conformance documents (`comments`, `strings`, `runes`,
  `integers`, `floats`, `identifiers`, `keywords`, and
  `statement-boundaries`), as whole files, lines, code spans, and code blocks
- every `.ore` file in `examples/`, `std/`, `benchmarks/`, and this folder
- 4,000 inputs generated from a fixed seed, plus fixed and 400 generated byte
  sequences for the UTF-8 check

Not compared:

- Diagnostic display text, notes, and labels. Rust formats characters in
  messages with its `Debug` escaping rules, which this stage does not
  reproduce. The Rust lexer tests keep checking that text.

## What writing it showed

- There are no enums, so token kinds, separators, and bases are integer
  constants with a tag field.
- `rune` does not convert to `int`, so the lexer decodes UTF-8 into integer
  code points itself.
- There are no package-level values, so each `Lex` call rebuilds the Unicode
  table.
- A call that borrows a value as `mut` cannot also read one of its Copy fields
  as an argument, for example `l.report(code, start, l.pos)`. The checker
  rejects the overlap, and the specification leaves exactly when borrows start
  open. The lexer copies the field into a local first.
